# Vut Distribution Format

Status: implemented (M4, M5, M15; release-manifest + provenance added by the
Production Release milestone). Assembly is performed by the `vut-dist` tool
(`crates/vut-dist`); release artifacts are produced per target and published as
a single GitHub Release in the public `duongonix/vut` repository.

## Artifact layout

Every artifact contains exactly:

```text
manifest.json            distribution metadata
version.json             build provenance (commit, Cranelift, profile)
LICENSE                  the Vut license
THIRD-PARTY-NOTICES.md   attribution for statically linked crates
bin/
  vut[.exe]
  vpm[.exe]
  vut-lsp[.exe]
lib/runtime/<target>/
  vut-core.lib    | libvut-core.a
  vut-stdlib.lib  | libvut-stdlib.a
  vut-startup.obj | vut-startup.o
std/
  <official stdlib .vut source>
linker/                  (reserved; populated only if a linker is bundled)
```

The official `.vut` stdlib source ships inside the artifact because the compiler
needs it when a program imports stdlib modules. No compiler, Rust workspace or
private source is included. The runtime archive staged is always the linkable
static archive (`vut_runtime.lib` / `libvut_runtime.a`), never the development
`.rlib`.

## Naming

```text
Windows:  vut-v<version>-<target>.zip
Unix:     vut-v<version>-<target>.tar.gz
```

Supported targets:

```text
x86_64-pc-windows-msvc        aarch64-pc-windows-msvc
x86_64-unknown-linux-gnu      aarch64-unknown-linux-gnu
x86_64-unknown-linux-musl     aarch64-unknown-linux-musl
x86_64-apple-darwin           aarch64-apple-darwin
```

Archives contain their contents at the archive root (`manifest.json`, `bin/`,
`lib/`, `std/`) so installers can extract directly into `VUT_HOME`.

## Manifest

`manifest.json` (inside each artifact and copied next to the archive as
`<dist>.manifest.json`):

```json
{
  "format_version": 1,
  "vut": "0.1.0",
  "vpm": "0.1.0",
  "stdlib": "0.1.0",
  "runtime": "0.1.0",
  "abi_version": 13,
  "target": "x86_64-unknown-linux-gnu",
  "archive": "vut-v0.1.0-x86_64-unknown-linux-gnu.tar.gz",
  "channel": "stable",
  "profile": "release",
  "cranelift": "0.135.2",
  "build_commit": "<git sha>",
  "minimum_os": "glibc-2.31"
}
```

`format_version` and `abi_version` gate compatibility; `target` and `archive`
gate integrity; `build_commit`, `cranelift` and `profile` record provenance;
`minimum_os` is optional.

## Release manifest (`releases.json`)

The release-level manifest is the single source installers use to resolve a
target. It is generated by `vut-dist release-manifest` and published both as a
release asset and as `releases.json` at the root of `duongonix/vut@main`.

```json
{
  "schema": 1,
  "channel": "stable",
  "version": "0.1.0",
  "released_at": "2026-01-01T00:00:00Z",
  "compiler": { "version": "0.1.0", "cranelift": "0.135.2", "profile": "release" },
  "runtime_abi": 13,
  "stdlib_version": "0.1.0",
  "manifest_format": 1,
  "targets": [
    {
      "triple": "x86_64-unknown-linux-gnu",
      "os": "linux",
      "arch": "x86_64",
      "libc": "glibc",
      "url": "https://github.com/duongonix/vut/releases/download/v0.1.0/vut-v0.1.0-x86_64-unknown-linux-gnu.tar.gz",
      "sha256": "<hex>",
      "size": 12345678,
      "archive": "vut-v0.1.0-x86_64-unknown-linux-gnu.tar.gz",
      "abi_version": 13,
      "minimum_os": "glibc-2.31",
      "sdk": { "windows_build_tools": false, "xcode_clt": false, "cc": true }
    }
  ]
}
```

Installers resolve `OS + arch + libc (+ version)` through `targets[]` and never
construct asset URLs themselves.

## Checksums

The release publishes `SHA256SUMS` listing every archive, and each target's
`sha256` is recorded in `releases.json`. Installers verify against the manifest
(mandatory) before extracting.

## Provenance

Each archive is attested with GitHub build provenance
(`actions/attest-build-provenance`). Because builds run in the source repository
(`vut_repo`), the attestation bundles (`<target>.sigstore.json`) are uploaded as
release assets so they are publicly verifiable:

```text
gh attestation verify <archive> --bundle <archive>.sigstore.json \
  --signer-workflow duongonix/vut_repo/.github/workflows/release.yml
```

## Tool

```text
vut-dist assemble \
  --target <triple> --out dist --bin-dir <release-dir> \
  --startup <startup-object> --vpm-version <vpm> --cranelift <ver> \
  --channel stable --license LICENSE --notices THIRD-PARTY-NOTICES.md \
  [--minimum-os <value>] [--build-commit <sha>]

vut-dist release-manifest \
  --dir dist --out dist/releases.json --repo duongonix/vut \
  --cranelift <ver> [--url-base <url-or-dir>] [--released-at <rfc3339>]
```

`assemble` copies the built binaries, stages the runtime archives under their
distribution names, copies the stdlib source, license and notices, writes
`manifest.json` and `version.json`, archives the tree, records a SHA-256
checksum, and writes `<dist>.manifest.json` next to the archive.
`release-manifest` merges those per-target manifests into `releases.json`.
